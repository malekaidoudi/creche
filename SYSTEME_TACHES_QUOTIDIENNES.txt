📋 VUE D'ENSEMBLE
═══════════════════════════════════════════════════════════════════════════════

Le système "Les tâches d'aujourd'hui" remplace "Rendez-vous d'aujourd'hui" et 
offre une solution complète pour gérer :

✅ Tâches personnalisées créées par le staff/admin
✅ Rendez-vous automatiques (depuis les inscriptions approuvées)
✅ Gestion des priorités (basse, normale, haute, urgente)
✅ Statuts de tâches (en attente, en cours, terminée, annulée)
✅ Interface fluide et moderne avec animations

🗄️ STRUCTURE BASE DE DONNÉES
═══════════════════════════════════════════════════════════════════════════════

Table: tasks
────────────────────────────────────────────────────────────────────────────

CREATE TABLE tasks (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  description TEXT,
  task_date TIMESTAMP NOT NULL,
  task_time TIME,
  task_type VARCHAR(50) DEFAULT 'custom',  -- 'custom' ou 'appointment'
  priority VARCHAR(20) DEFAULT 'normal',    -- 'low', 'normal', 'high', 'urgent'
  status VARCHAR(20) DEFAULT 'pending',     -- 'pending', 'in_progress', 'completed', 'cancelled'
  
  -- Relations
  enrollment_id INTEGER REFERENCES enrollments(id) ON DELETE CASCADE,
  created_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
  assigned_to INTEGER REFERENCES users(id) ON DELETE SET NULL,
  
  -- Métadonnées
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  completed_at TIMESTAMP
);

Index créés:
- idx_task_date (task_date)
- idx_task_status (status)
- idx_task_type (task_type)
- idx_enrollment_id (enrollment_id)
- idx_created_by (created_by)

🔌 API ENDPOINTS

      "description": "Discuter du comportement",
      "time": "10:00",
      "datetime": "2025-01-09T10:00:00Z",
      "priority": "high",
      "status": "pending",
      "creator": "Marie Dupont",
      "assigned": "Jean Martin"
    },
    {

      "enrollment_id": 45,

      "description": "Rendez-vous avec Fatima Ben Ali",

2. POST /api/tasks
────────────────────────────────────────────────────────────────────────────
Description: Créer une nouvelle tâche personnalisée
Accès: Staff/Admin
Body:
{
  "title": "Préparer activité peinture",
  "description": "Acheter matériel nécessaire",
  "task_date": "2025-01-09",
  "task_time": "15:30",
  "priority": "normal",
  "assigned_to": 5
}

Réponse:
{
  "success": true,
  "message": "Tâche créée avec succès",
  "task": { ... }
}

3. PATCH /api/tasks/:id/status
────────────────────────────────────────────────────────────────────────────
Description: Mettre à jour le statut d'une tâche
Accès: Staff/Admin
Body:
{
  "status": "completed"
}

Réponse:
{
  "success": true,
  "message": "Statut mis à jour",
  "task": { ... }
}

4. DELETE /api/tasks/:id
────────────────────────────────────────────────────────────────────────────
Description: Supprimer une tâche personnalisée
Accès: Staff/Admin
Réponse:
{
  "success": true,
  "message": "Tâche supprimée"
}

🔄 FLUX COMPLET
═══════════════════════════════════════════════════════════════════════════════

CRÉATION TÂCHE PERSONNALISÉE:
────────────────────────────────────────────────────────────────────────────
1. Staff/Admin clique sur "Ajouter"
2. Modal s'ouvre avec formulaire
3. Remplit: Titre, Description (opt), Heure (opt), Priorité
4. Clique sur "Ajouter"
5. API POST /api/tasks
6. Tâche ajoutée à la base de données
7. Liste rafraîchie automatiquement
8. Toast de succès affiché

RENDEZ-VOUS AUTOMATIQUE:
────────────────────────────────────────────────────────────────────────────
1. Admin approuve une inscription avec date RDV
2. Inscription enregistrée avec appointment_date
3. Le jour du RDV, l'API GET /api/tasks/today récupère:
   - Les tâches personnalisées du jour
   - Les inscriptions avec RDV du jour
4. Les RDV sont formatés comme des tâches de type "appointment"
5. Affichés dans la liste avec badge "RDV"
6. Contact parent cliquable (téléphone + email)

MARQUER COMME TERMINÉE:
────────────────────────────────────────────────────────────────────────────
1. Staff/Admin clique sur le cercle à gauche de la tâche
2. API PATCH /api/tasks/:id/status { status: "completed" }
3. Tâche marquée comme terminée (completed_at = now)
4. Visuel: Checkbox verte + texte barré + opacité réduite
5. Toast de succès
6. Note: Les RDV ne peuvent pas être marqués comme terminés

SUPPRIMER UNE TÂCHE:
────────────────────────────────────────────────────────────────────────────
1. Staff/Admin clique sur l'icône poubelle (tâches personnalisées uniquement)
2. Confirmation demandée
3. API DELETE /api/tasks/:id
4. Tâche supprimée de la base
5. Animation de sortie (slide left)
6. Toast de succès
7. Note: Les RDV ne peuvent pas être supprimés

🚀 DÉPLOIEMENT
═══════════════════════════════════════════════════════════════════════════════

Étapes:

1. Exécuter la migration sur la base de données:
   ```bash
   psql $DATABASE_URL -f backend/database/migrations/create_tasks.sql
   ```

2. Commiter les changements:
   ```bash
   git add .
   git commit -m "feat: Système de tâches quotidiennes avec RDV automatiques"
   git push
   ```

3. Render redéploie automatiquement le backend

4. Builder et déployer le frontend:
   ```bash
   cd frontend
   npm run build
   cp -r dist/* ../docs/
   cd ..
   git add docs/
   git commit -m "deploy: Système tâches quotidiennes"
   git push
   ```

5. Vérifier le déploiement:
   - Backend: https://creche-site.onrender.com/api/tasks/today
   - Frontend: https://malekaidoudi.github.io/creche
